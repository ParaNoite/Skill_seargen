# v0.8 结项说明

结项日期：2026-08-09

v0.8 的目标是把网页、视频和 GitHub 的主题证据合成为可复核的结论，而不是把各来源摘要简单拼接。融合阶段只读取用户已确认来源所产生的本地证据，不扩展搜索范围，也不额外调用远程模型。

## 已完成范围

- `topic process` 在来源处理完成后统一读取 `topic_package/evidence/*.json`。
- 网页正文句子、视频时间线条目、GitHub findings 或文件摘要被规范化为可定位的证据引用。
- 相近且极性一致的证据合并为共同结论，每条结论保留 1 到 3 个来源引用。
- 近似结论出现相反极性时写入 unresolved 冲突，不把它们伪装成一致结论。
- 单来源、弱证据、来源处理失败和未解决冲突进入证据缺口与风险标记。
- 视频标题和作者仅作为辅助元数据；ASR、字幕和视觉分析均未产生内容时，该视频必须失败，不能生成只有元数据的融合结论。
- 连续 ASR 切片会按时间合并为有长度上限的证据段，最多均匀保留 12 段；标题、作者和纯片头片尾话术不提升为结论，原始时间线仍完整保留。
- 中文 ASR 片段使用中文标点衔接，英文片段保持英文空格，避免融合文档出现逐片段空格断裂。
- 来源可信度汇总包含来源类型、质量分、风险标记、证据条目数和 high/medium/low 等级。
- 结构化结果写入 `topic_package/fusion.json`，面向人工阅读的结果写入 `topic_package/knowledge.md`。
- 普通模式、技术模式、纯视频和纯 GitHub 主题均可生成融合产物；单一来源会明确标为低置信或待复核。
- Web 主题详情展示融合产物路径、结论数、冲突数、缺口数和冲突复核提示。
- 旧主题 run 在加载时会补齐可选 fusion 路径；磁盘上没有融合产物时不会虚构 artifact。

## 产物契约

`topic_package/fusion.json` 包含：

- `schema_version`：当前为 `0.8`。
- `source_summary`：来源质量与可信度汇总。
- `conclusions`：共同结论、置信度、状态和最多三个引用。
- `conflicts`：未解决冲突及冲突双方引用。
- `evidence_gaps`：来源缺失、单来源类型、低置信和冲突缺口。
- `risk_flags`：主题级风险标记。

引用中的 `evidence_path` 相对主题 run，`locator` 使用网页句子序号、视频时间戳或 GitHub finding/文件路径。

## 不属于 v0.8

- 不生成技术模式最终 `SKILL.md` 或 `references/*.md` 体系；该能力属于 v0.9。
- 不使用模型裁决冲突，也不自动选择冲突中的“正确”一方。
- 不自动搜索补齐证据缺口，不扩大用户确认的来源集合。
- 不提供主题级自动评分或人工覆盖闭环。

## 验收方法

先运行离线回归：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_topic_fusion tests.test_topic_processing tests.test_topic_videos tests.test_web
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m skill_gather --help
node --check src\skill_gather\web_assets\app.js
git diff --check
```

然后使用已有配置完成一个至少选择两种来源类型的主题：

```powershell
.\.venv\Scripts\python.exe -m skill_gather topic create "Godot navigation" --mode technical --runs .\runs --config config.json
.\.venv\Scripts\python.exe -m skill_gather topic search <topic-run-id> --config config.json --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic candidates <topic-run-id> --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic select <topic-run-id> <candidate-id-1> <candidate-id-2> --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic process <topic-run-id> --config config.json --runs .\runs --vision-mode off
```

应确认：

- CLI 输出 `status` 为 `completed`，且 `fusion`、`knowledge` 路径非空。
- `fusion.json` 中每条关键结论有 1 到 3 个 citations。
- 单来源结论的 `low_confidence` 为 `true` 且状态为 `needs_review`。
- 有相反表述的 fixture 会进入 `conflicts`，不会被合并为 supported 结论。
- `knowledge.md` 明确列出关键结论、冲突记录、证据缺口、来源可信度和引用说明。
- Web 访问 `http://127.0.0.1:8765` 后，已完成主题显示融合统计与冲突复核提示。
