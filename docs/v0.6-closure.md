# v0.6 结项说明

结项日期：2026-08-05

v0.6 的目标是把 v0.1 的单视频处理链路接入主题任务：普通模式中用户确认公开视频候选后，系统为每个视频建立主题子 run，复用现有视频管线生成 `EvidenceTimeline`，并将成功视频证据写入主题包。

## 已完成范围

- `topic process` 支持处理普通模式中已确认的 `video` 来源。
- 每个视频来源会在主题 run 的 `video_runs/` 下创建子 run，并记录到 `TopicTask.video_runs`。
- 视频子 run 使用 `evidence_only` 模式，处理到 `timeline_merge` 后停止，不生成独立 `SKILL.md`、评分或候选包。
- 成功视频会在 `topic_package/evidence/video-<candidate-id>.json` 写入 manifest 和 `EvidenceTimeline`。
- 单个视频失败只写入该视频的子 run 状态和 `video_processing_audit.json`，不会吞掉其他视频的成功证据。
- 媒体下载前会检查累计视频时长预算；视觉阶段会按 `max_model_calls` 限制远程视觉调用上限。
- 主题子 run 默认复用缓存；显式 `refresh_cache` 会重建对应视频子 run。
- Web 详情页展示视频子 run、视频审计、视觉状态和失败原因；未配置 NewAPI API key 的视觉跳过原因会显示为中文。

## 不属于 v0.6

- 网页、视频和 GitHub 的统一结论融合不属于 v0.6。
- 技术模式 GitHub 处理属于 v0.7。
- 主题级最终评分、人工覆盖和完整工作台复核属于后续版本。
- v0.6 不承诺单视频都成功；它承诺失败可隔离、可审计，成功证据可进入主题包。

## 验收方式

CLI 验收：

```powershell
.\.venv\Scripts\python.exe -m skill_gather topic create "Godot 导航" --mode normal --runs .\runs --config config.json
.\.venv\Scripts\python.exe -m skill_gather topic search <topic-run-id> --config config.json --runs .\runs --fake
.\.venv\Scripts\python.exe -m skill_gather topic candidates <topic-run-id> --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic select <topic-run-id> <video-candidate-id-1> <video-candidate-id-2> --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic process <topic-run-id> --runs .\runs --config config.json --vision-mode off
.\.venv\Scripts\python.exe -m skill_gather topic inspect <topic-run-id> --runs .\runs
```

应确认：

- 至少一个视频成功时，命令输出 `status` 为 `completed`。
- `video_runs/` 下存在对应视频子 run。
- `topic_package/evidence/video-*.json` 中包含 `manifest` 和 `timeline`。
- `video_processing_audit.json` 中分别记录成功和失败视频。
- 失败视频不会删除或覆盖成功视频的主题 evidence。
- 纯视频主题不会生成或展示虚假的 `knowledge.md`。

Web 验收：

```powershell
npm run dev
```

访问 `http://127.0.0.1:8765` 后：

- 创建普通主题。
- 搜索并确认一个或多个视频候选。
- 在处理控件中选择视觉模式和帧数，点击处理已选来源。
- 完成后主题详情应展示视频子 run、视频审计路径、视觉状态和失败原因。
- 没有成功网页来源时，不应展示知识总结 artifact。
