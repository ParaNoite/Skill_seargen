主要依据，不以外部仓库热度替代本项目的真实问题。

| 已观测事实 | 数值 / 现象 | 对 v0.2 的含义 |
| --- | --- | --- |
| 公开 B 站样本的本地采集、抽帧、ASR 主链路 | 4 个样本中 3 个下载成功；成功样本共 80 帧、298 段 ASR、304 条证据 | 单视频采集和本地 ASR 已有可用基础，不是首要新能力缺口。 |
| 带密钥端到端验证 | 3 次；2 次蒸馏成功、1 次因 `invalid_distillation_json` 失败；从保存时间线重试后仍失败 | 结构化输出恢复、原始响应审计与退出码语义，是已发生而非假设的可靠性缺口。 |

### 数据获取说明

- 以上数值于本页标注日期通过已认证的 `gh api repos/<owner>/<repo>` 获取；API
  返回的 `updated_at` 全部为 2026-07-30，但本表为避免把“仓库元数据被更新”误作
  “代码推送”，使用 `pushed_at` 作为活跃度时间。
- 无认证的 `Invoke-RestMethod` 请求在本机先遇到连接关闭，获得受限网络权限后返回
  HTTP 403；因此改用本机已有 GitHub CLI 的已认证只读 API。没有使用搜索摘要、二手
  文章或记忆中的数字。
- `faster-whisper` 的“至多 4 倍”是其 README 的作者声明，未在本项目硬件、视频、
  模型和参数下复现，不能用于承诺 v0.2 的加速比例。
- VideoRAG 的算法 README 要求 Python 3.11、PyTorch、ImageBind、MiniCPM-V、Whisper
  等依赖，并以 RTX 3090 24GB 为示例；其 LICENSE 说明包含 ImageBind 的当前实现仅限
  非商业使用，框架架构部分才为 MIT。它只能作为设计参照，不能直接纳入项目依赖或商用
  路径，除非重新做许可证和依赖审查。

## 4. 可落地的 v0.2 范围建议

建议把 v0.2 定义为“**质量可测、失败可恢复、成本可比较**”，范围为 A 必做、B 受控
实验；C/D/F 不作为版本承诺。

### 立项验收应先固定的真实指标

1. **可靠性**：固定公开视频集上的阶段成功/失败数、自动重试次数、重试后成功数、
   非零退出码覆盖率，以及每个不可恢复失败的错误码和脱敏响应审计存在率。
2. **质量**：先写人工判定准则，再盲标候选为“可用 / 不可用 / 需修改”；报告规则、
   Judge 与人工标注的混淆矩阵。基线尚未建立，不能诚实地预先写成“达到 X%”。
3. **成本**：同一输入、同一机器和同一模型配置下，比较原始全帧视觉与 OCR/筛选方案的
   远程视觉调用数、墙钟时间、OCR/命令字段正确率；不将第三方 README 性能数字当结果。

### 明确不做

- 不将 VideoRAG 源码或其受限实现直接复制到 `third_party/` 或产品依赖中。
- 不用 cookie、付费、验证码或地区限制绕过来扩大 YouTube / 平台覆盖。
- 不在没有失败语义和预算控制前上线并发批量处理。
