# v1.1 研究自动化与前端重构计划

## 目标

v1.1 将当前本地 CLI 原型扩展为围绕研究任务运行的本地工作台：补齐模糊主题的 LLM 语义计划与确认流程，提供有安全门槛的全自动执行模式，并重构 Web 前端以承载运营、研究和结果浏览三个独立模块。

现版已可选地调用 LLM 扩展检索意图、评估候选，但结果会直接进入搜索，未向用户展示 LLM 如何理解模糊主题，也没有等待用户确认。v1.1 解决这一缺口。

## 前端工作台

前端采用 React + Vite，Python 后端继续提供本地 JSON API。页面使用统一导航和共享任务数据，但保持职责独立：

- 宏观运营页：任务队列、阶段、预算、耗时、模型可用性、失败原因、暂停、重试和全局指标。
- 研究工作台：语义计划、候选来源、自动或手动选源、执行进度、证据、风险和人工操作。
- 结果浏览器：按类型、状态、评分、风险和来源筛选，阅读、比较和导出知识包与 Skill。

视频 run、普通主题 run、技术主题 run 对前端暴露统一的工作项摘要；既有 `RunStore` 和 `TopicRunStore` 保持兼容，不进行破坏性的存储迁移。

## 模糊主题的 LLM 计划

仅当确定性规则判定主题范围过宽、歧义过高或关键实体不足时，任务进入计划阶段。明确主题保持现有直接搜索流程。

计划必须持久化为结构化数据，至少包含：歧义原因、2 至 4 个语义方案、推荐方案、目标、排除范围、研究维度、查询词、生成方式和审计状态。

- 手动模式：用户从多个语义方案中选择一项，并可编辑目标、范围、维度和查询词；确认后才允许搜索。
- 自动模式：记录推荐方案后自动继续。用户可中断计划生成；系统按已获得的保守计划继续，并记录 `plan_interrupted`。
- LLM 超时、不可用或输出无效：降级为确定性拆词与风险提示，要求用户确认后搜索。
- 不保存原始模型输出或密钥；只保存结构化计划和脱敏错误摘要。

## 全自动模式

任务创建时提供 `manual` 与 `auto` 执行模式。自动模式覆盖视频、普通主题和技术主题，自动推进计划、搜索、选源、处理、融合、生成和评分。

- 自动选源在预算内按质量和来源多样性工作：普通主题优先网页/视频，技术主题优先网页/GitHub/视频中可用的高质量来源；所有选择写入审计。
- 自动任务可在运营页暂停、重试和查看失败阶段。
- 只有证据充分、无冲突或缺口、无高风险标记、预算正常且评分达到标准阈值时才能自动标记为 `passed`。
- 其余任务仍可自动完成，但必须保留为 `needs_review` 或 `failed`。证据不足、来源冲突、外部服务失败或产物完整性不足不得自动发布。
- 单视频缺少交叉证据时默认不得自动 `passed`。

## 接口与状态

主题任务新增计划阶段、待语义确认状态、自动执行标记和计划中断审计；保留现有状态与 CLI 兼容。

新增或扩展以下 API 能力：

- 创建和读取研究计划。
- 选择、编辑、确认或中断语义方案。
- 启动、暂停、重试自动任务。
- 读取统一任务列表、任务详情、运营指标和结果筛选。
- 读取计划、选源、风险、预算和发布门槛的审计信息。

## 验收

- 单元测试：模糊判定、LLM 计划、规则降级、计划中断、自动选源、自动通过门槛和风险降级。
- API 测试：计划确认、自动执行、暂停、重试、统一工作项和结果筛选。
- React 组件与 Playwright 测试：三页面导航、语义方案选择、自动任务、视频/普通/技术主题全链路。
- 真实验收继续覆盖本地 ASR、公开视频、网页、GitHub 和 NewAPI。离线 fixture 只能验证契约，不能作为真实链路成功证据。

## 后续技术优化

- 以可取消的持久化作业队列、并发上限和事件流替代简单后台线程。
- 将预算细化到来源、模型、阶段和重试次数，提供成本预估、熔断和资源占用视图。
- 以人工复核反馈校准模糊判定、选源权重和自动通过门槛。
- 建立版本化真实基准回放，记录公开来源、模型版本、配置摘要、产物哈希和人工标签。
- 为 JSON API 建立版本前缀和 OpenAPI 契约；为前端建立组件库、设计令牌、无障碍与移动端测试。
- 扩展结果浏览器的全文索引、相似主题去重、Skill 版本比较和可追溯导出。
