# v1.1 研究自动化与前端工作台验收

## 交付范围

- 模糊主题规则判定、2 至 3 个结构化语义方案、推荐项、编辑确认和中断降级审计。
- `manual` / `auto` 主题执行模式，以及质量优先、来源多样、预算受限的自动选源。
- 自动发布门槛：交叉证据、冲突、缺口、风险、失败与标准评分共同决定 `passed` 或 `needs_review`。
- 统一工作项、运营指标、结果筛选、计划、暂停、重试和自动执行 JSON API。
- 运营、研究、结果三模块本地 Web 工作台；结果支持读取、最多三项比较和包含正文的 JSON 导出。
- LLM 计划在后台执行，可中断并丢弃迟到响应；主题处理在来源阶段边界响应暂停，视频任务支持暂停与重试。

旧 `RunStore`、`TopicRunStore` 和既有 CLI 命令继续读取 v1.0 JSON；新增字段都有兼容默认值，没有存储迁移。

## 自动化验收

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m skill_gather --help
node --check src\skill_gather\web_assets\app.js
```

当前回归基线为 216 项 `unittest`。浏览器验收使用 Playwright CLI 在 1440x900 与 390x844 视口检查三模块导航、筛选控件、任务操作和控制台错误。

专项测试位于 `tests/test_planning.py` 与 `tests/test_automation.py`，覆盖模糊判定、LLM/规则计划、计划确认、计划中断、自动选源和发布降级。`tests/test_web.py` 与 `tests/test_web_assets.py` 覆盖兼容 API 和静态前端契约。

## 人工验收

1. 运行 `.\scripts\dev.cmd`，打开 `http://127.0.0.1:8765`。
2. 确认顶部可切换“运营 / 研究 / 结果”，运营页显示统一任务指标，结果页可按状态筛选。
3. 在研究页以手动模式创建模糊主题“教程”，确认出现多个语义方案，选择后才允许搜索。
4. 以自动模式创建明确技术主题，勾选离线 fake 并启动自动执行；确认自动选源审计写入 `topic_state.json`。
5. 检查技术主题的 `topic_package/score.json` 与 `release_gate.json`；单来源、冲突、证据缺口、风险或低分必须保持 `needs_review`。

## 真实链路边界

离线 fake 只验证状态、计划、选源、API 和审计契约，不代表本地 ASR、Bilibili、网页、GitHub 或 NewAPI 可用。真实链路仍按 `docs/v1.0-closure.md` 的 smoke test 操作，并直接复核 `fusion.json`、`knowledge.md`、`SKILL.md`、`score.json` 与 `release_gate.json`。没有真实外部链路证据时不得把候选包宣称为可发布。
