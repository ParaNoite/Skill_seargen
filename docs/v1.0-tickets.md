## 01 - 定义 v1.0 主题任务与主题包契约

**Blocked by:** None - can start immediately.

**What to build:**  
为 v1.0 新增主题级任务和主题包的核心数据契约。系统要能表达一个从主题出发的任务，
而不是只能表达单个视频 run。

**Acceptance criteria:**

- [ ] 有结构化模型表达主题、模式、输出语言、候选来源、已选来源、预算、状态和产物索引。
- [ ] 普通模式和技术模式都能通过同一主题任务模型表达。
- [ ] 主题包结构能表达 `knowledge.md`、可选 `SKILL.md`、`references/`、`sources.json`、`score.json` 和 `evidence/`。
- [ ] 模型和 JSON 序列化测试覆盖普通模式、技术模式和缺失可选产物。
- [ ] 不破坏现有单视频 v0.1 数据模型和测试。

## 02 - 建立品牌显示名 `skill_seargen` 的兼容迁移

**Blocked by:** 01 - 定义 v1.0 主题任务与主题包契约.

**What to build:**  
把对外文档和 Web 显示名切换为 `skill_seargen`，同时保留现有 `skill_gather` 包名和
`skill-gather` CLI 命令作为兼容入口。

**Acceptance criteria:**

- [ ] README、Web 标题和用户可见文案使用 `skill_seargen`。
- [ ] 文档解释 `skill_seargen = search and generate`。
- [ ] `skill-gather` 命令和 `python -m skill_gather` 仍可用。
- [ ] 测试覆盖 Web 标题或品牌文本的更新。
- [ ] 不进行 Python 包目录重命名。

## 03 - 建立主题任务后台状态机与可恢复 run

**Blocked by:** 01 - 定义 v1.0 主题任务与主题包契约.

**What to build:**  
让主题任务可以作为后台阶段化 run 存储、恢复和检查状态。即使还没有真实搜索或生成，
也能创建主题 run、推进阶段、保存状态和重载状态。

**Acceptance criteria:**

- [ ] 主题 run 支持 `created`、`searching`、`awaiting_selection`、`processing_sources`、`generating`、`scoring`、`completed`、`failed` 等状态。
- [ ] 阶段、错误、产物路径和时间戳写入本地 run store。
- [ ] 重启进程后能读取已有主题 run 状态。
- [ ] CLI 或内部 API 能 inspect 主题 run。
- [ ] 单元测试覆盖正常推进、失败记录和恢复读取。

## 04 - 增加预算、缓存和 Judge 难度配置

**Blocked by:** 01 - 定义 v1.0 主题任务与主题包契约; 03 - 建立主题任务后台状态机与可恢复 run.

**What to build:**  
给主题任务增加默认开启的预算控制、缓存策略和 Judge 难度设置。预算先作为强约束记录和校验，
后续来源处理必须读取这些配置。

**Acceptance criteria:**

- [ ] 配置支持最大候选数、最大处理来源数、最大视频时长、最大模型调用或费用估算、最长运行时间。
- [ ] 配置支持缓存复用和显式刷新。
- [ ] Judge 难度支持 `lenient`、`standard`、`strict`、`off`。
- [ ] 超出预算时任务进入可解释失败或等待人工调整状态。
- [ ] 测试覆盖默认值、配置覆盖、非法值和预算触发。

## 05 - 实现 SearchProvider 抽象和离线搜索夹具

**Blocked by:** 01 - 定义 v1.0 主题任务与主题包契约; 04 - 增加预算、缓存和 Judge 难度配置.

**What to build:**  
建立可配置搜索提供方接口，并先用离线 fake provider 跑通搜索到候选结果的链路，避免后续
真实网络搜索阻塞核心流程。

**Acceptance criteria:**

- [ ] SearchProvider 输入主题、查询列表、预算和模式，输出规范化候选。
- [ ] 候选包含 URL、标题、摘要、来源类型、查询来源、相关性理由和初始风险。
- [ ] 离线 fake provider 可用于测试普通模式和技术模式。
- [ ] 搜索结果写入主题 run 和 `sources.json` 草稿。
- [ ] 测试不依赖真实网络。

## 06 - 实现查询扩展与搜索审计记录

**Blocked by:** 05 - 实现 SearchProvider 抽象和离线搜索夹具.

**What to build:**  
用户输入主题后，系统生成少量受限查询扩展，并保留每个查询、模型版本、生成理由和候选命中记录。

**Acceptance criteria:**

- [ ] 查询扩展数量受预算限制。
- [ ] 原始主题查询始终保留。
- [ ] 每个候选能追溯到触发它的查询。
- [ ] 查询扩展失败时可降级为只使用原始主题。
- [ ] 测试覆盖成功扩展、降级和审计记录。

## 07 - 接入首个通用网页搜索提供方

**Blocked by:** 05 - 实现 SearchProvider 抽象和离线搜索夹具; 06 - 实现查询扩展与搜索审计记录.

**What to build:**  
接入 v1.0 首个真实可配置的通用网页搜索提供方，使主题能发现视频、网页和 GitHub 候选。

**Acceptance criteria:**

- [ ] 搜索提供方通过配置启用，不写死密钥或端点。
- [ ] 搜索错误、限流、空结果和网络失败有可解释错误。
- [ ] 搜索结果经过统一候选模型输出。
- [ ] 搜索响应不记录 API key、cookie 或不可提交的敏感信息。
- [ ] 有 fake 测试覆盖 provider 行为；真实 provider 至少有可跳过的 smoke test 说明。

## 08 - 实现候选来源规范化、去重和质量评分

**Blocked by:** 05 - 实现 SearchProvider 抽象和离线搜索夹具; 07 - 接入首个通用网页搜索提供方.

**What to build:**  
把搜索结果变成用户可筛选的候选清单。系统要识别来源类型、合并重复链接、给出质量分和风险标记。

**Acceptance criteria:**

- [ ] 能识别视频、网页文本、GitHub 仓库和未知来源。
- [ ] 默认展示约 20 个候选，并受预算控制。
- [ ] 去重能处理相同 URL、规范化 URL 和明显重复标题。
- [ ] 网页质量评分考虑可信度、完整度、相关性、重复度和广告/SEO 风险。
- [ ] 候选卡片数据包含标题、来源、摘要、质量评分、风险和推荐理由。

## 09 - 实现 Web/CLI 的主题创建与候选确认流程

**Blocked by:** 03 - 建立主题任务后台状态机与可恢复 run; 08 - 实现候选来源规范化、去重和质量评分.

**What to build:**  
让用户能在 Web 和 CLI 中创建主题任务、选择普通/技术模式、查看候选列表，并确认哪些来源进入重处理。

**Acceptance criteria:**

- [ ] Web 支持主题输入、模式选择、预算摘要和候选确认。
- [ ] CLI 支持等价主题创建、搜索、列候选和提交选择。
- [ ] 用户确认前不进入下载、抓取、ASR、视觉或生成等高成本阶段。
- [ ] 选择记录写入主题 run 和 `sources.json`。
- [ ] 测试覆盖普通模式、技术模式、无候选和用户未选择来源。

## 10 - 实现网页文本源抓取、快照和证据提取

**Blocked by:** 03 - 建立主题任务后台状态机与可恢复 run; 04 - 增加预算、缓存和 Judge 难度配置; 09 - 实现 Web/CLI 的主题创建与候选确认流程.

**What to build:**  
处理用户确认的网页文本来源，提取正文、保留轻量快照，并生成可被后续融合使用的文本证据。

**Acceptance criteria:**

- [ ] 只处理公开网页，不处理登录、cookie 或付费内容。
- [ ] 网页正文、标题、来源 URL、抓取时间和风险标记写入证据。
- [ ] 保存轻量文本快照，不保存敏感请求头或 cookie。
- [ ] 抓取失败时记录来源级失败，不拖垮整个主题任务。
- [ ] 测试覆盖成功抓取、低质量网页、重复网页和抓取失败。

## 11 - 将现有视频管线接入主题任务来源处理

**Blocked by:** 03 - 建立主题任务后台状态机与可恢复 run; 04 - 增加预算、缓存和 Judge 难度配置; 09 - 实现 Web/CLI 的主题创建与候选确认流程.

**What to build:**  
复用现有单视频处理能力，把用户确认的视频来源作为主题任务的子来源处理，并将视频证据汇入主题级证据集合。

**Acceptance criteria:**

- [ ] 主题任务可以调度一个或多个公开视频来源。
- [ ] 视频处理复用现有 metadata、抽帧、ASR、视觉和 EvidenceTimeline 能力。
- [ ] 最大视频时长和模型调用预算能限制视频处理。
- [ ] 视频失败生成来源级失败审计，主题任务可继续处理其他来源。
- [ ] 不支持 cookie、付费、验证码、地区限制或受限内容。

## 12 - 实现技术模式 GitHub 轻量分析与 skill 来源降级

**Blocked by:** 03 - 建立主题任务后台状态机与可恢复 run; 04 - 增加预算、缓存和 Judge 难度配置; 09 - 实现 Web/CLI 的主题创建与候选确认流程.

**What to build:**  
技术模式处理公开 GitHub 来源，默认分析 README、docs、examples、配置和入口文件；当深度分析不可用时，可降级吸收已有 Codex / Anthropic skill 格式材料。

**Acceptance criteria:**

- [ ] 非技术模式不默认处理 GitHub。
- [ ] 技术模式能从公开 GitHub 来源提取 README、文档、示例、配置和入口摘要。
- [ ] 不处理私有仓库，不记录 token。
- [ ] 能识别 `SKILL.md` 或类似 skill 格式材料作为降级来源。
- [ ] GitHub 失败不拖垮整个主题任务，并写入来源级审计。

## 13 - 实现多来源证据融合和冲突记录

**Blocked by:** 10 - 实现网页文本源抓取、快照和证据提取; 11 - 将现有视频管线接入主题任务来源处理; 12 - 实现技术模式 GitHub 轻量分析与 skill 来源降级.

**What to build:**  
把网页、视频和 GitHub 证据融合成主题级证据集合，抽取共同结论、分歧结论、来源支持和证据缺口。

**Acceptance criteria:**

- [ ] 融合结果保留来源类型、来源 URL、证据通道和时间戳或文本位置。
- [ ] 关键结论能关联 1 到 3 个证据引用。
- [ ] 冲突说法必须保留并解释来源差异。
- [ ] 证据不足的结论标记低置信或待复核。
- [ ] 测试覆盖多来源一致、来源冲突、单来源证据和无足够证据。

## 14 - 生成普通模式 `knowledge.md`

**Blocked by:** 13 - 实现多来源证据融合和冲突记录.

**What to build:**  
普通模式根据主题级证据生成中文快速整合总结，帮助用户快速理解这批资料说了什么。

**Acceptance criteria:**

- [ ] `knowledge.md` 包含主题摘要、关键点、步骤或方法、冲突说法、风险和来源引用。
- [ ] 默认中文输出，英文术语、命令和 API 名称保留原文。
- [ ] 文档不伪装成完整教材，不强制生成实操测试。
- [ ] 关键结论使用结论级证据引用。
- [ ] 普通模式不生成 `SKILL.md`。

## 15 - 生成技术模式 `SKILL.md` 与 `references/`

**Blocked by:** 13 - 实现多来源证据融合和冲突记录; 14 - 生成普通模式 `knowledge.md`.

**What to build:**  
技术模式在生成知识文档之外，生成工具/流程型主 skill，并将细节拆入 `references/*.md`。

**Acceptance criteria:**

- [ ] 技术模式生成主 `SKILL.md` 和至少一个需要时可引用的 `references/*.md`。
- [ ] 主 skill 聚焦触发条件、适用边界、执行流程和 references 路由。
- [ ] 子文档承载细节、示例、命令、配置或扩展步骤。
- [ ] 文档教人，skill 给模型执行，两者不简单重复。
- [ ] 对不适合工具/流程型 skill 的主题生成 `needs_review` 或失败审计。

## 16 - 实现 v1.0 自动评分与最终状态

**Blocked by:** 14 - 生成普通模式 `knowledge.md`; 15 - 生成技术模式 `SKILL.md` 与 `references/`.

**What to build:**  
对知识文档和技术模式 skill 进行分维度自动评分，并输出 `passed`、`needs_review` 或 `failed`。

**Acceptance criteria:**

- [ ] 普通模式评分覆盖 `knowledge.md`。
- [ ] 技术模式评分覆盖 `knowledge.md` 和 `SKILL.md`。
- [ ] 评分维度包含证据充分性、准确性、结构清晰、可学习或可执行、边界和风险。
- [ ] `passed` 只表示值得人工确认，不自动入库。
- [ ] `score.json` 记录 Judge 难度、维度分、最终状态和解释。

## 17 - 实现失败审计、人工覆盖和重跑入口

**Blocked by:** 03 - 建立主题任务后台状态机与可恢复 run; 16 - 实现 v1.0 自动评分与最终状态.

**What to build:**  
主题任务失败或低分时，系统输出可行动审计；用户可以强制加入来源、调整 Judge 难度、把失败结果提升到 `needs_review`，并按阶段重跑。

**Acceptance criteria:**

- [ ] 失败审计列出已搜索来源、已选来源、完成阶段、失败阶段、失败原因和证据缺口。
- [ ] 审计包含新增来源、调整预算、调整 Judge 难度或重跑阶段的建议。
- [ ] 用户可强制加入来源并重跑后续阶段。
- [ ] 用户可将 `failed` 提升为 `needs_review`，但不能伪造成自动 `passed`。
- [ ] 人工覆盖记录写入 `score.json` 或 metadata，并可复核。

## 18 - 完成本地 Web 研究工作台体验

**Blocked by:** 09 - 实现 Web/CLI 的主题创建与候选确认流程; 14 - 生成普通模式 `knowledge.md`; 15 - 生成技术模式 `SKILL.md` 与 `references/`; 16 - 实现 v1.0 自动评分与最终状态; 17 - 实现失败审计、人工覆盖和重跑入口.

**What to build:**  
把 v1.0 主题任务主流程收束到本地 Web 工作台，让用户能从主题输入一路走到候选确认、运行监控、证据浏览、评分查看和产物预览。

**Acceptance criteria:**

- [ ] Web 支持主题输入、模式选择、配置引导和预算摘要。
- [ ] Web 支持候选来源卡片展示和人工确认。
- [ ] Web 支持后台任务进度、失败状态和可重跑入口。
- [ ] Web 支持查看证据、冲突、评分和最终产物。
- [ ] 页面刷新后仍能恢复查看已有主题 run。

## 19 - 建立 v1.0 固定验收集和回归检查

**Blocked by:** 16 - 实现 v1.0 自动评分与最终状态; 17 - 实现失败审计、人工覆盖和重跑入口; 18 - 完成本地 Web 研究工作台体验.

**What to build:**  
建立 10 个主题的 v1.0 验收集和可重复检查流程，用来判断普通模式、技术模式、失败审计和评分解释是否达标。

**Acceptance criteria:**

- [ ] 验收集覆盖普通教程、技术工具、中文材料、英文材料、视频、网页、GitHub、低质量来源、多来源冲突和证据不足输入。
- [ ] 普通模式多数 `knowledge.md` 自动评分为 `passed`。
- [ ] 技术模式多数 `knowledge.md` 和 `SKILL.md` 达到 `needs_review` 以上。
- [ ] 所有 `failed` 都有明确失败审计和可重跑建议。
- [ ] 回归命令记录在文档中，并可在无真实 API key 的情况下跑离线路径。

## 推荐实施顺序

1. 先完成 01 到 04，建立主题任务、状态、预算和配置底座。
2. 再完成 05 到 09，跑通搜索、候选评分和人工确认。
3. 然后完成 10 到 13，接入网页、视频、GitHub 三类来源并融合证据。
4. 接着完成 14 到 17，生成普通文档、技术 skill、评分和失败审计。
5. 最后完成 18 到 19，把 Web 工作台和固定验收集补齐。

任何工单如果需要真实网络、真实模型或第三方服务，应先提供 fake/offline 测试路径，再补
可跳过的 smoke test。
