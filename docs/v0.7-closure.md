# v0.7 结项说明

结项日期：2026-08-05

v0.7 的目标是让技术模式开始可用：用户确认公开 GitHub 仓库候选后，系统可以在不 clone 仓库、不使用 token/cookie、不执行代码的前提下，提取 README、docs、examples、配置文件、入口文件和已有 skill 格式材料的轻量证据。

## 已完成范围

- `topic process` 支持处理技术模式中已确认的 `github` 来源。
- 普通模式不会把 GitHub 当作网页强行处理；如果只选 GitHub，会记录跳过原因并失败提示。
- GitHub 处理仅读取公开 `github.com/<owner>/<repo>` 仓库。
- GitHub 处理通过公开仓库元信息、仓库树和少量文本文件做轻量分析，不 clone 仓库、不下载第三方源码、不执行代码。
- 成功 GitHub 来源会写入：
  - `topic_package/evidence/github-<candidate-id>.json`
  - `topic_package/references/github-<candidate-id>.md`
  - `github_processing_audit.json`
- 轻量分析会提取安装、命令、API/入口、示例、配置、约束和已有 Codex / Anthropic skill 材料信号。
- 已有 skill/Agent 格式材料只作为参考降级处理，并标记 `github_existing_skill_material_downgraded`，不直接当作最终 skill 输出。
- 技术模式仍可同时处理网页和公开视频来源；GitHub-only 技术主题也能凭 GitHub 证据完成处理阶段。

## 不属于 v0.7

- 不处理私有仓库、token、cookie、登录态或受限内容。
- 不 clone 完整仓库，不长期保存第三方源码。
- 不执行仓库代码，不安装仓库依赖。
- 跨网页、视频和 GitHub 的结论融合属于 v0.8。
- 技术模式最终 `SKILL.md`、`references/*.md` 体系化生成和评分闭环属于 v0.9。

## 验收方式

CLI 离线验收：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_topic_processing tests.test_source
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m skill_gather --help
```

CLI 真实公开仓库验收：

```powershell
.\.venv\Scripts\python.exe -m skill_gather topic create "Godot navigation" --mode technical --runs .\runs --config config.json
.\.venv\Scripts\python.exe -m skill_gather topic search <topic-run-id> --config config.json --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic candidates <topic-run-id> --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic select <topic-run-id> <github-candidate-id> --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic process <topic-run-id> --runs .\runs
.\.venv\Scripts\python.exe -m skill_gather topic inspect <topic-run-id> --runs .\runs
```

应确认：

- 命令输出 `status` 为 `completed`。
- 命令输出 `successful_github_sources` 大于 `0`。
- `topic_package/evidence/github-*.json` 存在，且包含 `files`、`findings`、`limitations`。
- `topic_package/references/github-*.md` 存在，且能看到安装、命令、API/入口、示例、配置或约束信号。
- `github_processing_audit.json` 记录成功、失败和跳过来源。
- 不应出现仓库 clone、token、cookie、完整第三方源码或运行日志入仓。

Web 验收：

```powershell
npm run dev
```

访问 `http://127.0.0.1:8765` 后：

- 创建技术主题。
- 搜索并确认 GitHub 候选。
- 点击处理已选来源。
- 完成后主题详情应显示 GitHub 审计 artifact。
- 后端 run 目录中应出现 GitHub evidence JSON 和 reference Markdown。
