# skill_seargen v0.1 到 v1.0 版本路线图

本文档描述项目从当前 v0.1 原型逐步演进到 v1.0 完整版本的版本计划。
它关注“每个版本应该新增什么能力”，而不是具体开发工单。

## 路线总览

| 版本 | 版本主题 | 核心新增能力 | 版本完成后应该能做到 |
|---|---|---|---|
| v0.1 | 单视频 skill 蒸馏原型 | B 站单公开视频处理、抽帧、ASR、视觉/OCR、EvidenceTimeline、RIA++ skill、评分、失败审计 | 用户给一个 B 站公开视频 URL，系统能生成候选 skill 或失败审计包 |
| v0.2 | 质量可测、失败可恢复 | 失败退出码、蒸馏 JSON 修复/重试、脱敏模型响应审计、Judge 校准、人工标注基线、低成本初筛 | 系统失败原因可解释，评分结果可复核，批处理前的可靠性基础补齐 |
| v0.3 | 主题任务雏形 | 主题级 RunState、主题包结构、普通/技术模式、预算配置、缓存策略、品牌显示名 `skill_seargen` | 系统不再只围绕单视频，而能表达“围绕一个主题做研究”的任务 |
| v0.4 | 搜索与候选确认 | SearchProvider 抽象、查询扩展、通用网页搜索、候选来源规范化、去重、质量评分、候选确认 Web/CLI 流程 | 用户输入主题后，系统能搜出候选材料，并让用户选择哪些来源进入分析 |
| v0.5 | 网页文本知识总结 | 网页抓取、正文提取、轻量快照、网页证据、普通模式 `knowledge.md` 生成、网页质量风险标记 | 普通模式可用：用户输入主题并确认网页/视频候选后，能得到中文快速整合总结 |
| v0.6 | 多视频主题处理 | 将现有视频管线接入主题任务、多视频证据汇总、视频级失败隔离、视频预算控制 | 一个主题可以处理多个公开视频来源，并把视频证据汇入同一主题包 |
| v0.7 | 技术模式与 GitHub 来源 | 技术主题识别、GitHub 轻量分析、README/docs/examples/配置/入口提取、已有 skill 格式材料降级 | 技术模式可用：技术主题可同时参考视频、网页和 GitHub 证据 |
| v0.8 | 多来源证据融合 | 跨来源证据融合、结论级引用、冲突记录、证据缺口标记、来源可信度汇总 | 系统能把多个来源整合成有引用、有冲突说明、有风险标记的主题证据 |
| v0.9 | 技术 skill 生成与复核闭环 | 技术模式 `SKILL.md`、`references/*.md`、文档+skill 分维度评分、人工覆盖、按阶段重跑、失败审计增强 | 技术模式能产出主 skill + 子文档，并提供评分、风险、人工复核和重跑能力 |
| v1.0 | 本地 Search + Generate 工作台 | 完整 Web 工作台、CLI 主流程、固定 10 主题验收集、离线回归、预算/缓存/评分稳定化、文档完善 | 个人研究者可以用本地 Web 从主题出发，完成搜索、筛选、分析、生成、评分和复核 |

## v0.1：单视频 skill 蒸馏原型

当前 v0.1 的目标是跑通单个 B 站公开视频到候选 skill 的主链路。

应包含：

- B 站单公开视频 URL 识别。
- 元数据和媒体采集。
- 抽帧和音频提取。
- 本地 faster-whisper ASR。
- newapi 视觉/OCR、蒸馏和 Judge。
- EvidenceTimeline。
- RIA++ skill 候选包。
- 规则评分 + LLM Judge。
- `passed`、`needs_review`、`failed` 状态。
- 失败审计包。
- `score`、`inspect`、`mvp-check` 等基础 CLI。
- 临时 Web 页面用于提交视频、查看 run 和 MVP 自检。

不做：

- 主题搜索。
- 批量处理。
- YouTube。
- GitHub 来源。
- 普通知识文档。
- 多来源融合。

## v0.2：质量可测、失败可恢复

v0.2 不急着扩来源，而是先修复 v0.1 已暴露的可靠性和评分问题。

应加入：

- `video` 最终状态为 `failed` 时返回非零退出码。
- 蒸馏 JSON 解析失败时的有限重试或结构修复。
- 脱敏原始模型响应、解析错误和重试记录。
- 规则评分、Judge 评分、人工复核结果分开记录。
- Judge 难度和阈值校准。
- 固定小规模视频基准集。
- 人工标注准则。
- 评分混淆矩阵或等价质量报告。
- 低成本初筛原型，拒绝明显无效输入。
- 本地 OCR / 帧筛选 A/B 实验入口。

完成标准：

- 失败能被 CLI、Web 和后续批处理可靠识别。
- 蒸馏失败能解释原因，并能复用已有 timeline 重试。
- 评分不再只看总分，而能说明证据、结构、边界或风险问题。

## v0.3：主题任务雏形

v0.3 开始从“单视频处理”过渡到“围绕主题研究”。

应加入：

- 对外品牌显示名改为 `skill_seargen`。
- 保留 `skill_gather` 包名和 `skill-gather` 命令作为兼容入口。
- 新增主题任务模型。
- 新增主题级 run 状态。
- 新增普通模式和技术模式字段。
- 新增主题包结构。
- 新增预算配置。
- 新增缓存复用策略。
- 新增主题 run 的创建、读取、失败记录和恢复。

完成标准：

- 系统可以创建一个主题任务，即使还不具备完整搜索和生成能力。
- 主题任务能表达普通模式与技术模式。
- 主题包能表达未来的 `knowledge.md`、`SKILL.md`、`references/`、`sources.json`、`score.json` 和 `evidence/`。

## v0.4：搜索与候选确认

v0.4 让用户从“给 URL”升级为“给主题后先找候选材料”。

应加入：

- `SearchProvider` 抽象。
- 离线 fake search provider，用于无网络测试。
- 查询扩展。
- 通用网页搜索提供方。
- 搜索结果规范化。
- 来源类型识别：视频、网页、GitHub、未知来源。
- 候选去重。
- 候选质量评分。
- 候选风险标记。
- Web 候选卡片。
- CLI 候选列表和选择命令。

默认行为：

- 输入主题后展示约 20 个候选。
- 用户选择约 5 个来源进入后续处理。
- 用户确认前不进入下载、抓取、ASR、视觉或生成阶段。

完成标准：

- 用户可以输入主题，看到候选来源清单，并选择要分析的来源。
- 每个候选能说明为什么相关、有什么风险、来自哪个查询。

## v0.5：网页文本知识总结

v0.5 让普通模式先可用。此阶段重点是网页文本来源和 `knowledge.md`。

应加入：

- 公开网页抓取。
- 正文提取。
- 网页文本轻量快照。
- 网页来源质量评分。
- 网页文本证据结构。
- 普通模式中文 `knowledge.md` 生成。
- 结论级证据引用。
- 多网页冲突说法记录。
- 网页抓取失败的来源级审计。

完成标准：

- 用户输入一个普通教程主题，确认网页候选后，系统能输出中文快速整合总结。
- 总结说明资料主要讲了什么、关键步骤是什么、来源是否冲突、哪些地方证据不足。

## v0.6：多视频主题处理

v0.6 把 v0.1 的单视频管线纳入主题任务，让一个主题可以处理多个公开视频。

应加入：

- 主题任务调度多个视频来源。
- 视频子 run 与主题 run 的父子关系。
- 视频证据汇入主题级 evidence。
- 视频级失败隔离。
- 最大视频时长预算。
- 视频视觉/ASR 成本预算。
- 多视频缓存复用。

完成标准：

- 一个主题可以选择多个公开视频进行处理。
- 单个视频失败不会导致整个主题失败。
- 视频证据能和网页证据放入同一个主题证据集合。

## v0.7：技术模式与 GitHub 来源

v0.7 让技术模式开始可用，GitHub 作为技术主题的额外证据来源。

应加入：

- 技术主题识别。
- 技术模式显式入口。
- 公开 GitHub 仓库来源识别。
- README 分析。
- `docs/`、`examples/`、配置文件和入口文件轻量分析。
- GitHub 文件摘要和关键片段证据。
- Codex / Anthropic skill 格式材料识别。
- GitHub 深度分析不可控时的现有 skill 降级路径。

完成标准：

- 普通模式不强行处理 GitHub。
- 技术模式能从公开 GitHub 仓库提取用法、安装、命令、API、示例或约束。
- 私有仓库、token、cookie 和受限内容不进入 v1.0 范围。

## v0.8：多来源证据融合

v0.8 解决“多来源材料如何合成一个可信结论”的问题。

应加入：

- 网页、视频、GitHub 证据统一融合。
- 共同结论抽取。
- 冲突结论保留。
- 来源支持关系。
- 证据缺口标记。
- 结论级引用。
- 低置信结论标记。
- 来源可信度汇总。

完成标准：

- 关键结论能追溯到 1 到 3 个来源证据。
- 多来源冲突必须明确列出，不能假装一致。
- 单来源或弱证据结论必须标记低置信或待复核。

## v0.9：技术 skill 生成与复核闭环

v0.9 完成技术模式的核心输出和复核机制。

应加入：

- 技术模式主 `SKILL.md` 生成。
- `references/*.md` 子文档生成。
- 工具/流程型 skill 模板。
- 不适合 skill 化主题的拒绝或降级。
- 文档评分。
- skill 评分。
- 分维度 `score.json`。
- 人工强制加入来源。
- 调整 Judge 难度后重跑。
- 将 `failed` 提升为 `needs_review` 的人工覆盖。
- 按阶段重跑。
- 失败审计增强。

完成标准：

- 技术主题能输出知识文档 + 主 skill + references。
- 文档教人，skill 给模型执行，两者不简单重复。
- 自动评分能解释证据、准确性、结构、可执行性、边界和风险问题。
- 人工覆盖不能伪造证据，也不能把失败产物伪装成自动 `passed`。

## v1.0：本地 Search + Generate 工作台

v1.0 是完整版本，重点是把前面能力收束成稳定可用的本地工作台。

应加入或完成：

- 完整本地 Web 工作台。
- CLI 覆盖主题主流程。
- Web 配置引导。
- 主题输入。
- 普通模式 / 技术模式选择。
- 预算摘要。
- 候选确认。
- 后台任务进度。
- 证据浏览。
- 冲突查看。
- 评分查看。
- 产物预览。
- 页面刷新后恢复已有主题 run。
- 固定 10 个主题验收集。
- 离线回归测试路径。
- 真实服务 smoke test 说明。
- README 和文档更新。

完成标准：

- 个人研究者可以在本地 Web 中从主题出发完成搜索、筛选、分析、生成、评分和复核。
- 普通模式多数验收主题的 `knowledge.md` 自动评分为 `passed`。
- 技术模式多数验收主题的 `knowledge.md` 和 `SKILL.md` 达到 `needs_review` 以上。
- 所有 `failed` 都有失败审计和可重跑建议。
- 同一主题重跑能复用缓存。
- 系统不会在人工确认候选后擅自扩大到无预算的额外来源。

## v1.0 明确不做

- 不做公开 SaaS。
- 不做多用户协作。
- 不做云端托管。
- 不接 cookie。
- 不处理付费内容、验证码、地区限制或其他访问控制内容。
- 不处理私有 GitHub 仓库。
- 不自动发布或入库生成的 skill。
- 不做无限爬取或无预算搜索。
- 不长期保存完整大视频或完整仓库 clone。

## 推荐节奏

| 阶段 | 推荐版本 | 判断重点 |
|---|---|---|
| 可靠性补强 | v0.2 | 先把失败、评分和审计做稳 |
| 主题化底座 | v0.3 | 让系统能表达主题任务和主题包 |
| 搜索入口 | v0.4 | 让主题能找到候选材料 |
| 普通模式可用 | v0.5 | 先交付中文快速知识总结 |
| 多视频增强 | v0.6 | 复用已有视频优势 |
| 技术模式材料 | v0.7 | 接入 GitHub 和现有 skill 来源 |
| 证据融合 | v0.8 | 解决多来源一致、冲突和引用 |
| 技术 skill 输出 | v0.9 | 完成 skill 生成、评分和复核 |
| 完整工作台 | v1.0 | 收束成稳定本地产品体验 |
