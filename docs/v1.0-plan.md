# skill_seargen v1.0 立项计划

> `skill_seargen` 取义于 search and generate。v1.0 对外品牌先使用
> `skill_seargen`，但为了降低迁移成本，Python 包名和 CLI 命令在本阶段暂时保留
> `skill_gather` / `skill-gather`。

## 1. 项目定位

v1.0 的目标是把当前单视频 skill 蒸馏原型，演进为一个面向个人研究者的本地
Search + Generate 工作台：

```text
主题
  -> 查询扩展
  -> 通用网页搜索
  -> 候选来源评分与人工确认
  -> 视频 / 网页 / GitHub 证据处理
  -> 多来源证据融合
  -> 知识文档，或知识文档 + skill
  -> 自动评分 + 人工复核
```

v1.0 不是公开视频下载器、爬虫平台、公开 SaaS 或多人协作系统。它的核心价值是：

- 自动搜罗和筛选与主题相关的公开资料。
- 将多来源材料整合为可复核的中文知识总结。
- 在技术模式下生成可供模型使用的工具/流程型 skill 候选包。
- 保留证据、来源、评分、风险和失败审计，方便人工判断是否采用。

## 2. 用户与模式

### 2.1 核心用户

v1.0 面向个人研究者和自用工作流，不面向公开产品用户，也不承担团队权限、
多用户协作、云端托管或公开发布级风控。

### 2.2 普通模式

普通模式是默认模式。用户输入主题后，系统搜索和分析公开视频、网页、博客、
教程和官方文档，并输出中文知识文档。

普通模式的知识文档不是完整教材，而是快速整合总结：

- 这批资料主要讲了什么。
- 关键概念、步骤、方法和注意事项。
- 多个来源之间的一致结论和冲突说法。
- 来源质量、证据缺口和风险提示。

### 2.3 技术模式

技术模式需要用户显式选择。它用于编程、AI 工具、开发流程、调试流程、配置流程等
工具/流程型技术主题。

技术模式在普通模式材料之外，额外启用 GitHub 来源，并输出：

- 给人读的中文知识文档。
- 给模型使用的主 `SKILL.md`。
- 放在 `references/` 下的子技能或细节文档。

知识文档负责教人理解主题，skill 负责指导模型在具体任务中执行。两者共享证据，
但不应简单互相复制。

## 3. 搜索与来源策略

### 3.1 搜索入口

v1.0 使用可配置的 `SearchProvider` 抽象。首发版本实现一个通用网页搜索提供方，
后续可扩展到 B 站、YouTube、GitHub 或其他搜索源。

输入主题后，系统会生成少量受限查询扩展，并记录每个候选结果来自哪个查询。
查询扩展必须可审计，不能无限扩散。

### 3.2 候选确认

默认流程是先搜索，再让用户确认候选来源，之后才进入下载、抓取、转写、视觉理解、
仓库分析和模型生成等高成本阶段。

默认规模：

- 搜索后展示约 20 个候选。
- 用户选择约 5 个来源进入重处理。
- 候选卡片展示标题、来源、摘要、时长或仓库指标、相关性理由、质量评分和风险标记。

### 3.3 来源类型

普通模式支持：

- 公开视频。
- 网页文本。
- 博客、教程页和官方文档。

技术模式额外支持：

- 公开 GitHub 仓库。
- GitHub 上已有的 Codex / Anthropic skill 格式材料，作为技术模式的降级来源。

### 3.4 来源筛选

来源筛选按主题类型动态排序：

- 技术主题优先视频、网页和 GitHub 互证。
- 非技术主题优先视频和网页文本，不强行使用 GitHub。

网页来源进入质量评分筛选，评分至少考虑：

- 来源可信度。
- 内容完整度。
- 与主题的相关性。
- 重复度。
- 广告、软文、SEO 或复制站风险。

当多个来源说法不一致时，文档必须明确列出冲突、支持来源和推荐采用的说法，
不能把冲突压平成单一结论。

## 4. 产物包

v1.0 的输出单位是主题包，而不是单个视频包。

普通模式主题包：

```text
topic-package/
  knowledge.md
  metadata.json
  sources.json
  score.json
  evidence/
```

技术模式主题包：

```text
topic-package/
  knowledge.md
  SKILL.md
  metadata.json
  sources.json
  score.json
  evidence/
  references/
    *.md
```

核心文件职责：

- `knowledge.md`：中文快速整合总结，面向人阅读。
- `SKILL.md`：技术模式主 skill，负责触发条件、适用边界、执行步骤和 references 路由。
- `references/*.md`：技术模式的子技能、细节步骤、示例和扩展材料。
- `metadata.json`：主题、模式、模型、预算、版本、状态和产物索引。
- `sources.json`：搜索候选、用户选择、来源质量评分、风险和去重信息。
- `score.json`：自动评分维度、Judge 难度、最终状态和人工覆盖记录。
- `evidence/`：网页文本快照、视频关键帧索引、音频片段索引、GitHub 文件摘要和结构化证据。

证据引用采用结论级引用。每个关键结论、步骤或风险判断应能追溯到 1 到 3 个来源证据。

## 5. GitHub 分析边界

技术模式默认对 GitHub 仓库做轻量但可复核的分析：

- README。
- `docs/`。
- `examples/`。
- 配置文件。
- 入口文件。
- 明确暴露用法、命令、API 或插件结构的关键文件。

v1.0 不默认做完整源码理解，也不把整个仓库作为长期保存产物。如果 GitHub 深度分析在
v1.0 实现上不可控，可以降级为只搜索和吸收已有 Codex / Anthropic skill 格式材料。

## 6. 运行、缓存与预算

v1.0 本地 Web 是主入口，CLI 保留同等主流程能力。Web 至少覆盖：

- 主题输入。
- 普通模式 / 技术模式选择。
- 配置引导。
- 搜索候选确认。
- 任务进度。
- 证据浏览。
- 评分结果。
- 产物预览。

主题任务采用后台可恢复的阶段化 run。刷新页面或中断后，应能继续查看状态，并支持按阶段重跑。

默认缓存策略：

- 搜索结果可复用。
- 抓取材料可复用。
- ASR、OCR、视觉理解和证据分析结果可复用。
- 重跑默认复用缓存，用户可显式刷新。

默认保存轻量快照：

- 保存网页文本快照。
- 保存视频关键帧、音频片段索引和必要证据。
- 保存 GitHub 文件摘要和关键片段。
- 不长期保存完整大视频或完整仓库 clone。

预算控制默认开启，至少包括：

- 最大候选数。
- 最大处理来源数。
- 最大视频时长。
- 最大模型调用或费用估算。
- 最长运行时间。

并发采用有限并发：

- 网页抓取和下载可以小并发。
- 视觉、蒸馏、Judge 等模型阶段必须限流。

## 7. 评分、复核与失败处理

v1.0 的自动评分覆盖知识文档和技术模式 skill。

评分维度至少包括：

- 证据充分性。
- 准确性。
- 结构清晰度。
- 可学习性或可执行性。
- 边界清晰度。
- 安全与合规风险。

最终状态沿用：

- `passed`：自动评分认为值得人工确认。
- `needs_review`：有明显风险或证据不足，但仍有复核价值。
- `failed`：不建议使用，需要补充来源、调整参数或重跑。

`passed` 不代表自动入库。v1.0 生成的文档和 skill 必须经过人工复核后才能采纳。

Judge 难度支持：

- `lenient`
- `standard`
- `strict`
- `off`

失败时必须保留失败审计包，说明：

- 已搜索和已选择的来源。
- 完成阶段和失败阶段。
- 失败原因。
- 可用证据和缺失证据。
- 建议新增来源、调整 Judge 难度、改变预算或重跑阶段。

人工覆盖允许：

- 强制加入某个来源。
- 调整 Judge 难度后重跑。
- 将 `failed` 提升为 `needs_review`。

人工覆盖不得伪造证据，也不得把自动失败产物直接伪装成自动 `passed`。

## 8. 安全、合规与非目标

v1.0 只处理公开可访问材料。

明确不做：

- 不做公开 SaaS。
- 不做多用户协作。
- 不做云端托管。
- 不接 cookie。
- 不处理付费内容、验证码、地区限制或其他访问控制内容。
- 不处理私有 GitHub 仓库。
- 不自动发布或入库生成的 skill。
- 不做无限爬取或无预算搜索。
- 不将大视频、完整仓库 clone、模型输出日志、API key、cookie、token 或个人绝对路径提交进 Git。

任何第三方依赖、搜索提供方或本地后端进入实现前，都必须记录来源、版本、许可证和调用边界。

## 9. v1.0 验收标准

固定 10 个主题作为 v1.0 验收集，覆盖：

- 普通教程主题。
- 技术工具或流程主题。
- 中文材料。
- 英文材料。
- 视频来源。
- 网页文本来源。
- GitHub 来源。
- 低质量来源。
- 多来源冲突。
- 证据不足或不可处理输入。

验收采用分模式达标：

- 普通模式：多数 `knowledge.md` 自动评分为 `passed`。
- 技术模式：多数 `knowledge.md` 和 `SKILL.md` 达到 `needs_review` 以上。
- 所有 `failed` 结果都有明确失败审计和可重跑建议。
- 评分结果能解释是证据问题、生成问题、结构问题、边界问题还是风险问题。
- 同一主题重跑能复用缓存，不重复执行已完成的高成本阶段。
- 人工确认候选来源后，系统不会擅自扩大到无预算的额外来源。

常规检查仍沿用仓库默认命令：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m skill_gather --help
```

涉及 Web 主流程时，还应验证本地 Web 入口：

```powershell
.\scripts\dev.cmd
```
