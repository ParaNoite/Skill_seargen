# 游戏核心循环设计

从玩家重复执行的最小动作开始设计：输入产生反馈，反馈改变风险或资源，玩家据此决定下一步。把内容扩展放在核心循环稳定之后。

## 执行步骤

1. 用一句话定义玩家目标和每局结束条件。
2. 列出输入、即时反馈、资源变化和风险变化。
3. 画出开始、进行中、暂停、失败、胜利和重启的状态转换。
4. 为每个转换写出可观察的 UI 反馈与最小测试动作。
5. 删除不能服务核心循环的功能，先做一局可完成的网页原型。

## 完成标准

- 玩家目标、失败条件和重启方式明确。
- 每个核心动作都有可见反馈和可测试结果。
- 设计文档标明未实现内容，不把概念描述当成已完成玩法。

## 边界

这是早期玩法设计工具，不替代数值平衡、商业化、内容评级或最终用户研究。
